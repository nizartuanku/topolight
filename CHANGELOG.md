## 0.4.0 — 2026-09-03

- Routing & L2 (v0.4): BGP4-MIB peers (state, remote AS, uptime, last error decoded, accepted prefixes from CISCO-BGP4-MIB), OSPF-MIB neighbours and router ID, Q-BRIDGE VLANs with member ports (PortList decoding), spanning tree (root bridge, root port/cost, forwarding/blocking ports, topology-change counter), IEEE8023-LAG bundles and members — walked every 5 minutes with the endpoint tables. Device → Routing & L2 tab; `GET /api/devices/{id}/routing`, `GET /api/routing`. Events and rules: `bgp_neighbor_down/up`, `bgp_prefixes_dropped`, `ospf_adjacency_down/up`, `stp_root_changed`, `stp_topology_change`, `lag_member_down/up`.
- Wireless and SD-WAN (v0.4): `internal/integ` reads controllers and cloud APIs — **UniFi Network** (UniFi OS and classic controller: login, `stat/device`; APs, switches, gateways with clients per radio and SSID, channel, width, tx power, utilisation, firmware/upgradable, satisfaction, WAN1/WAN2 state) and **Cisco Meraki** (Dashboard API v1: organisations, devices, statuses, MX uplinks with loss/latency, wireless clients per AP and SSID). Imported devices are *managed* (`unifi:<id>`, `meraki:<id>`): the controller's word is their status; they are not polled directly and count towards the licence cap. Over SNMP the poller now reads **Cisco WLC** (AireOS/9800, AIRESPACE-WIRELESS-MIB: AP table, radios, channel utilisation, clients per SSID) and **Aruba mobility controllers** (WLSX-WLAN-MIB) — APs become managed devices under the controller — and **FortiGate SD-WAN** health checks (fgVWLHealthCheckLinkTable: state, latency, jitter, loss per member). New **Wireless & WAN** page (`g w`: access points, WAN paths), Device → Wireless / WAN tab (radios, SSIDs, client history, WAN paths with latency history), Admin → Integrations (add/edit/test/run). Series `wifi_clients|<dev>`, `wifi_aps_up|<controller>`, `sdwan_up|latency|jitter|loss|<dev>|<path>/<if>`. Rules `sdwan_link_down` (Major, resolves on recovery), `sdwan_degraded` (Minor; ≥ 250 ms or ≥ 5 % loss), `integration_failed` (Minor, resolves on the next good run). `GET/POST /api/integrations`, `PUT/DELETE /api/integrations/{id}`, `POST /api/integrations/{id}/test|run`, `GET /api/wireless`, `GET /api/sdwan`, `GET /api/devices/{id}/wireless`.
- gNMI / OpenConfig (v0.4, beta): `internal/gnmi` — a standard-library gRPC client (HTTP/2 over TLS or plaintext h2c, hand-encoded protobuf) for gNMI Capabilities and Get. A credential of type **gNMI** (user, password, port, TLS/plaintext, self-signed) polls `/system/state` (hostname, uptime from boot-time, software version), `/system/cpus`, `/system/memory/state` and `/interfaces` (name, ifindex, description, admin/oper status, ethernet port-speed, MAC, 64-bit counters) with JSON_IETF; the same device and interface samples, rates, alerts and graphs as SNMP. Credential **Test** shows the gNMI version and models; **Add device** takes a credential (gNMI is tried only when chosen). Verified against a real gRPC (grpcio) target in both TLS and h2c modes. Routing/L2, endpoints, temperature and vendor health still come from SNMP.
- Vendor profiles: pfSense/OPNsense, VyOS, Arista EOS, Extreme EXOS, HPE Comware, Dell OS10, Ruckus ICX, Check Point, SonicWall, WatchGuard, Sophos, Zyxel, TP-Link, Meraki (SNMP), Cisco WLC, Aruba controller, Cambium.
- Credentials: `kind` is now `""` (SNMP), `ssh` or `gnmi`; discovery and the SNMP fallback pick SNMP credentials only.
- Cluster (v0.3): `internal/cluster` — cluster CA + per-node certificates (mutual TLS on `-cluster-listen :8434`), single-use join tokens carrying the CA fingerprint (`install.sh --join URL --token T [--role collector]`, or `-join/-join-token`), replicated membership, lease-based leader election with majority quorum (heartbeat 2 s, lease 10 s, election 10–15 s), rendezvous-hash device sharding with per-site pins, data mirroring of the whole data directory to standbys every 10 s (journal tails, atomic whole files), forwarding of samples/events/metrics/syslog/traps/flows from standbys and collectors to the leader with a 200k-item buffer, standby console that proxies to the leader, role changes by process re-exec, `-promote` for two-node clusters, removed nodes shut out by certificate CN. Leader keeps inventory walks for remotely polled devices; TSDB checkpoints every minute in a cluster. Admin → Cluster: enable, join tokens (full/collector), members with heartbeat/mirror age/polls, remove, pin sites. Verified with three processes plus a collector: join, sharding, failover in 12 s, old leader rejoining as standby, site pin moving all devices to the collector.
- **Console port is now 8433** (was 8432, which collided with another Hexward tool). Existing installs keep whatever `-listen` says in `/etc/topolight/topolight.env`; the installer prints a note if it sees 8432 there. Docker images expose 8433.
- Reports: availability/SLA (downtime from device_down alerts, journal-backed), alerts by rule/device with MTTR, busiest interfaces and device load from the TSDB, inventory with vendor summary, configuration changes and change/reboot events, flow talkers/applications, endpoints by vendor/switch, probe OK rates; HTML (print to PDF) and CSV; saved definitions with daily/weekly/monthly e-mail schedule (HTML mail), last 12 copies kept in `<data>/reports/`; Reports page (`g r`) with quick report; `GET /api/reports/preview`, `/api/reports` CRUD, `POST /api/reports/{id}/run?mail=1`. Store gained `AlertsSince` and `EventsSince` journal readers.
- Configuration backup: SSH credentials (password/key, enable, port) per site or device; `internal/backup` pulls the running configuration with per-vendor recipes (interactive shell with pager handling and enable, or exec for Junos/MikroTik/Linux), normalises volatile lines, stores gzipped versions (50 per device) with +/− counts, Myers line diff with hunks; scheduled every 24 h (Admin → Settings, per device) and 2 minutes after a `config_changed` syslog event; Device → Config backup tab with viewer, download and A/B diff; `config_backup_changed` and `config_backup_failed` events; `GET /api/devices/{id}/configs[/{ver}[/diff/{other}]]`, `POST /api/devices/{id}/backup`, `GET /api/configs`. First external dependency: golang.org/x/crypto/ssh (via the GitHub mirror in go.mod replace directives).
- Probes: synthetic checks (tcp, http with status/body, dns with expected answer and resolver, tls with expiry/chain, ping, traceroute over raw ICMP) scheduled per probe, latency series `probe_ms|<id>`, `probe_failed` (after 2 failures) and `tls_expiring` alerts that self-resolve, `path_changed` events; Probes page (`g p`) with chart, recent runs and path; `GET/POST /api/probes`, `PUT/DELETE /api/probes/{id}`, `POST /api/probes/{id}/run`.
- SNMPv3 traps and informs: authenticated (MD5/SHA/SHA-256) and decrypted (AES/DES) with the saved v3 credentials, keys localised per sender engine ID and cached; informs acknowledged; counters and last error in Admin → System.
- Syslog over TLS (RFC 5425) on TCP/6514 (`-syslog-tls-listen`), with the console certificate, `-syslog-tls-cert/-key`, or a self-signed certificate created in `<data>/syslog-tls.crt` (fingerprint logged); optional `-syslog-tls-client-ca`. TCP and TLS accept RFC 6587/5425 octet counting (embedded newlines included) and newline framing.
- Ping-only devices: add a host without SNMP (device dialog or per-site "keep hosts that answer ping but no SNMP"); ICMP reachability/RTT/loss/jitter and the matching alerts, no `snmp_unreachable` noise.
- API tokens: Admin → Users → + Token; `Authorization: Bearer tl_…` on every endpoint with the token's role; SHA-256 at rest, shown once, revocable, last-used tracked.
- Endpoints: MAC forwarding tables (Q-BRIDGE-MIB, BRIDGE-MIB, Cisco IOS per-VLAN via community indexing or the `vlan-N` SNMPv3 context) and ARP/ND tables (ipNetToMediaTable, ipNetToPhysicalTable) are walked every 5 minutes. Each MAC is placed on its access port (ports with an LLDP/CDP neighbour, a topology link or another monitored device's chassis MAC are uplinks; otherwise the port with the fewest learned MACs wins), joined with the IP from ARP and the vendor from the IEEE OUI registry (embedded, 53k entries). New Endpoints page (`g e`) with search by MAC / IP / vendor / port, Device → Endpoints tab per port, `endpoint_moved` events, `GET /api/endpoints`. Snapshot in `<data>/endpoints.json`; entries silent for 90 days are pruned; 200k cap.
- Flow: NetFlow v5/v9 and IPFIX on UDP/2055, sFlow v5 on UDP/6343 (`-flow-listen`, `-sflow-listen`; `""` disables). Records are matched to devices by exporter address and summarised per exporter into 1-minute (last hour) and 5-minute (24 h, persisted as `<data>/flow/<day>.jsonl`, gzipped after the day) top-N buckets: 100 talkers/targets, 200 conversations, 50 applications, every interface. New Flow page (`g f`) and Device → Flow tab with throughput chart and tables; new endpoints `GET /api/flow`, `/api/flow/exporters`, `/api/flow/series`; Admin → System shows datagram/record/template counters. Config snippets gained the export commands for IOS/IOS-XE, NX-OS, FortiGate, Junos, MikroTik and Aruba sFlow. Installer, Dockerfile and compose expose the two ports.
- Licence: no more feature gating. Free, Pro and Team differ only in capacity and history (25 / 500 / 1,500 devices; 1 / 3 / unlimited sites; 7 / 183 / 365 days; 3 / 5 / unlimited users). Telegram, webhook, maintenance windows, roles and the export API work in every tier.
- Charts: wider value gutter so `1.5 Mb/s`-style labels are not clipped.
- Topology: hovering a node shows a health card — status/cause, CPU, memory, temperature, RTT/loss, interface counts (up/down/shut, uplinks down), aggregate in/out bit/s and packets/s, packet drops and errors per second, the three busiest ports, and the ports that are admin-up but down. The same card sits in the click-through side panel. New endpoint `GET /api/devices/{id}/health` (viewer), computed from the last samples in the store.
- Polling: IF-MIB unicast packet counters (ifHCIn/OutUcastPkts, 32-bit fallback) and ifIn/OutDiscards are now collected; every interface carries `in_pps`, `out_pps`, `in_drop_rate`, `out_drop_rate` in the API. History: packet rates are stored for important interfaces only, drop series only while drops occur — the documented per-port storage cost is unchanged.

## 0.1.0 — 2026-09-02

First release.

- Discovery: subnet/range sweep (ICMP + SNMP v2c/v3), LLDP/CDP neighbour follow-up, manual add; licence caps reported honestly (over-cap devices listed as *not monitored*).
- Polling: ICMP RTT/loss/jitter; SNMP sysUpTime, IF-MIB with 64-bit counters, HOST-RESOURCES, ENTITY-MIB; vendor profiles for Cisco IOS/NX-OS/ASA, FortiGate, Palo Alto, Juniper, Aruba AOS-S/CX, MikroTik, Huawei, Ubiquiti, net-snmp + user JSON profiles; reboot detection.
- Topology: links from both ends of LLDP/CDP observations with confidence, role inference (core pair / distribution / access), stacked-disc 3D map on a plain canvas with 2D mode, status and utilisation overlays, live updates.
- Intake: syslog UDP/TCP (RFC 3164/5424, Cisco mnemonics, FortiGate key=value) with per-source flood control; SNMP v2c traps and informs with storm limiting.
- State engine: confirmation cycles, hysteresis, flap detection, topology-aware suppression with alert folding, site-down collapse, maintenance windows, dedup and 30-minute re-open, event rules with auto-resolve.
- Notifications: e-mail (SMTP/STARTTLS), Telegram, HMAC-signed webhook; grouping, quiet hours, minimum severity, test button.
- Storage: JSON snapshot + JSONL journals + a compact time-series store (deflated chunks, 60-s raw for 7 days, 5-minute rollups to retention); measured ≈4.5 KB/series/day raw, ≈1.8 KB/series/day rollup.
- Console: setup wizard, overview, topology, alerts with keyboard, devices and device detail, logs with histogram, admin; dark/light; WCAG AA (axe clean); CSP, same-origin checks, PBKDF2 passwords.
- Packaging: static binaries for linux/amd64, linux/arm64, darwin, windows; installer with capabilities and hardened systemd unit; Dockerfile; Apache-2.0.

Known limits are listed in the README under *Honest limits*.
